# Exercise 7.8: Export for issue: IFC4, levels, base quantities

**Goal.** Export the finished TB-01 model for issue, with base quantities.

## What you build

- Schema IFC4, SI units.
- Every element in a level.
- Base quantities (Qto_...BaseQuantities with the volume) on every column, beam, slab, wall and footing, matching the geometry (with a short script if your program cannot calculate them).
- Save as tb01_issue.ifc.

The numbers of section 7 that are not in the [project brief](../../brief/README.md) are given above.

## In FreeCAD

The issue file is your native `tb01.ifc` of section 4: it is already IFC4 in metres, with every element in a level. What it lacks is base quantities. FreeCAD's classic export (File > Export with Manage > Manage IFC Quantities ticks) writes only its own set ElementQuantities, not Qto_...BaseQuantities. In a native IFC document the same dialog offers the Qto sets (Add quantity set...), but FreeCAD 1.1.3 fills them with 0 there. So you add them with a short script.

1. Open your `tb01.ifc` of section 4 (File > Open…, **All individual IFC objects**, **Load the shape (slower)**, **Locked (IFC objects only)**).
2. File > Save IFC File As…, `tb01_issue.ifc`.
3. View > Panels > Python Console. Run:
   ```python
   import ifcopenshell.api, ifcopenshell.geom, ifcopenshell.util.shape as us
   f = FreeCAD.ActiveDocument.Proxy.ifcfile
   s = ifcopenshell.geom.settings()
   for cls in ("IfcColumn", "IfcBeam", "IfcSlab", "IfcWall", "IfcFooting"):
       for e in f.by_type(cls):
           shape = ifcopenshell.geom.create_shape(s, e)
           vol = us.get_volume(shape.geometry)
           q = ifcopenshell.api.run("pset.add_qto", f, product=e, name="Qto_" + cls[3:] + "BaseQuantities")
           ifcopenshell.api.run("pset.edit_qto", f, qto=q, properties={"NetVolume": vol})
   FreeCAD.ActiveDocument.Modified = True
   ```
   Each concrete element gets Qto_ColumnBaseQuantities, Qto_BeamBaseQuantities and so on, with NetVolume computed from its own geometry (openings already cut).
4. Keep `shape = ...` on its own line as written: reading `.geometry` straight from `create_shape(...)` reads freed memory and gives wrong numbers.
5. File > Save IFC File (Ctrl+S).
6. Check the schema: the first lines of `tb01_issue.ifc` (open it in a text editor) read `FILE_SCHEMA(('IFC4'));`.

## In Bonsai

Bonsai saves IFC natively, so "export" means checking the file and adding base quantities.

1. Open your finished `tb01.ifc`. **Project Overview > Project Info** shows **IFC Schema** IFC4. Units are SI (metres).
2. Check that every element is in a level: in **Project Overview > Grouping and Filtering > Search**, run the query `IfcElement, location=NULL`. Rebars, columns and the rest should not appear; if something does, assign its **Spatial Container**.
3. Deselect all (Alt+A). Go to **Costing and Scheduling > Quantity Take-off** ("Quantifying All Objects"), choose the rule **IFC4 Base Quantities - IfcOpenShell** and click **Perform Quantity Take-off**.
4. Select a column and open **Object Information > Object > Quantity Sets**: Qto_ColumnBaseQuantities with NetVolume 0.536 (0.4 x 0.4 x 3.35). The slab shows 63.06 with the openings deducted.
5. If you change geometry later, run the take-off again: quantities do not update themselves.
6. Choose **File > Save IFC Project As...** and save as `tb01_issue.ifc`.
7. Optional: **Quality and Coordination > Quality Control > Debug > Validate IFC File** checks the file against the IFC schema.

## Check your work

Save or export your work as `tb01_issue.ifc`, then run this from the course folder:

```
python -m bimcheck 7.8 tb01_issue.ifc
```

Every line should say PASS. A FAIL line tells you what was expected and what was found.

## Why this matters

The issued IFC is what the client, the contractor and the checker receive. Export settings decide whether quantities, properties and the spatial structure arrive intact.
