# Exercise 6.2: Revisions on the sheet

**Goal.** Record two revisions on sheet S-101.

## What you build

- Revision **A**, 'First issue', with a date.
- Revision **B**, 'Core walls revised', with a date.
- Show them in a revision table on the sheet (a revision schedule or a table placed on the sheet) and export it again.

All numbers come from the [project brief](../../brief/README.md) and its [drawings](../../brief/drawings/).

## In FreeCAD

1. Open `tb01.FCStd` with the sheet of 6.1.
2. Annotation > Text above the title block texts, as a small table: `Rev  Description  Date`.
3. Annotation > Text on the next line: `A    First issue    2026-10-12` (use your own date, written year-month-day).
4. Annotation > Text on the line below: `B    Core walls revised    2026-11-06`.
5. Set **Font Size** `200 mm` for the three lines and line them up with Modify > Move if needed. Draw lines between the rows with 2D Drafting > Line if you want a ruled table.
6. Select everything you exported in 6.1 plus the three revision lines.
7. File > Export…, **Flattened SVG (*.svg)**, save over `sheet.svg`.
8. Commit the new sheet together with the model when you use Git (exercise 7.3), so the revision and the file change together.

## In Bonsai

Bonsai has no revision manager. It can place a spreadsheet on a sheet as a schedule, so you keep the revision table in a small spreadsheet and put it on S-101. The title block already has a REV field and a revision table header.

1. In LibreOffice Calc, make a sheet with three columns:

   | REV | DESCRIPTION | DATE |
   |---|---|---|
   | A | First issue | 2026-10-12 |
   | B | Core walls revised | 2026-11-06 |

   Type each date with a leading apostrophe (`'2026-10-12`) so it stays as text.
2. Select A1:C3 and choose **Format > Print Ranges > Define**, so Bonsai reads only these cells. Save as `revisions.ods` in the folder of `tb01.ifc`.
3. In Bonsai go to **Drawings and Documents > Schedules**, click the import icon (**Load Schedules**), then **Add Schedule** and pick `revisions.ods`.
4. With the schedule active, click **Build Schedule** (the numbered-lines icon). Bonsai converts it to `revisions.svg`.
5. Go to **Sheets**, make S-101 active and click **Add Schedule To Sheet**. The table is placed on the sheet; move it next to the title block in Inkscape if you like (it is the sheet layout under `layouts/`).
6. Click **Create Sheets** again and open the sheet. It shows the revision table with A and B, their descriptions and dates.
7. Copy `sheets/S-101 - LEVEL 1 FRAMING PLAN.svg` as `sheet.svg` again.
8. When you issue revision C later, add a row to `revisions.ods`, click **Build Schedule** and **Create Sheets**. Commit the change with Git (7.3) so the history stays with the model.

## Check your work

Save or export your work as `sheet.svg`, then run this from the course folder:

```
python -m bimcheck 6.2 sheet.svg
```

Every line should say PASS. A FAIL line tells you what was expected and what was found.

## Why this matters

Revisions are the audit trail of a design. Contractors build from the latest revision; a missing or wrong revision is one of the most common causes of building from an old drawing.
