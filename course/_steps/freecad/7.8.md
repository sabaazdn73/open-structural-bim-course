The issue file is your native `tb01.ifc` of section 4: it is already IFC4 in metres, with every element in a level. What it lacks is base quantities. FreeCAD's classic export (File > Export with Manage > Manage IFC Quantities ticks) writes only its own set ElementQuantities, not Qto_...BaseQuantities. In a native IFC document the same dialog offers the Qto sets (Add quantity set...), but FreeCAD 1.1.3 fills them with 0 there. So you add them with a short script.

1. Open your `tb01.ifc` of section 4 (File > Open…, **All individual IFC objects**, **Load the shape (slower)**, **Locked (IFC objects only)**).
2. File > Save IFC File As…, `tb01_issue.ifc`.
3. View > Panels > Python Console. Run:
   ```python
   import ifcopenshell.api, ifcopenshell.geom, ifcopenshell.util.shape as us
   f = FreeCAD.ActiveDocument.Proxy.ifcfile
   s = ifcopenshell.geom.settings()
   for cls in ("IfcColumn", "IfcBeam", "IfcSlab", "IfcWall", "IfcFooting"):
       for e in f.by_type(cls):
           shape = ifcopenshell.geom.create_shape(s, e)
           vol = us.get_volume(shape.geometry)
           q = ifcopenshell.api.run("pset.add_qto", f, product=e, name="Qto_" + cls[3:] + "BaseQuantities")
           ifcopenshell.api.run("pset.edit_qto", f, qto=q, properties={"NetVolume": vol})
   FreeCAD.ActiveDocument.Modified = True
   ```
   Each concrete element gets Qto_ColumnBaseQuantities, Qto_BeamBaseQuantities and so on, with NetVolume computed from its own geometry (openings already cut).
4. Keep `shape = ...` on its own line as written: reading `.geometry` straight from `create_shape(...)` reads freed memory and gives wrong numbers.
5. File > Save IFC File (Ctrl+S).
6. Check the schema: the first lines of `tb01_issue.ifc` (open it in a text editor) read `FILE_SCHEMA(('IFC4'));`.
